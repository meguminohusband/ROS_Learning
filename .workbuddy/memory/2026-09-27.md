## 修复 cone_color_guesser 的「左红右蓝」不稳定问题（同一会话，主任务）

用户反馈实测无法稳定输出左红右蓝。**做外科式修改，未推倒重写**——只有 `assignColors` 一个函数和投票锁定逻辑是坏的，
TF 处理、杂点过滤、发布、launch、rviz 都保持原样。

### 实测确认的根因（都有数据支撑）

1. **配对歧义**：锥桶沿赛道间隔中位 **2.31 m** < 赛道宽 **3.07 m**，尺度重叠；按帧内距离贪心配对时
   **74% 的最近邻是同一侧相邻锥桶** → 配对中点不在赛道中线上 → 推出的方向是错的。
2. **索引错位**：`mids` 按距离排序后，循环里仍用 `pairs[k]` 取值，方向与配对不是同一对。
3. **单对退化反向**：只有一对时 `dir = -mid`（指向车），与多对情况左右正好相反。
4. **车后方反向**：对车后方的锥桶，「车头朝向」与行进方向相反 → 红蓝互换。
5. **过早永久锁定（最致命）**：`min_observations=3`，头 3 帧就锁死。诊断表里一条锥桶观测 214 次、
   红票 0 蓝票 3 —— 锁在了最早（车辆几乎没动、无路径可用）的错误颜色上。

### 修法

以「车辆在 imu_map 下走过的路径」的切向作为行进方向基准（直接测量，非反推），路径自地图原点起算。
- 锥桶投影到路径 → 最近点 + 该处切向 d；左侧 = z × d，侧向偏移 s 的符号即颜色。
- **只有投影落在「已驶过路径内部」（`path_margin` 米以内）的观测才算满权票**；车前方用降权（`head_weight`）。
- 锁定要求：加权票 >= `min_votes` **且满权票 >= `min_reliable_votes`**。
- 已锁定的锥桶不再因 miss 删除（否则车开过去后输出数量会忽上忽下）。

### 顺带修掉的两个真 bug

- **TF 查询超时**：按 stamp 查询必然失败（时钟差 171.78 天），`ros::Duration(0.2)` 导致**每帧白等 200 ms**，
  节点只能跑 5 Hz。改成 `ros::Duration(0.0)` 非阻塞后每帧 8-25 ms。—— 这个必须记牢。
- **`pcl::PointXYZRGB` 的 alpha 未初始化** → `rgb` float 可能是 NaN/Inf → 下游用 `skip_nans=True`
  读点云时**红色点整批消失**（实测抓取只剩 28 个全蓝点，而节点实际发 60 个）。

### 验证结果

- 离线因果回放（`tools/sim_algorithms.py`，600 帧）：单帧 50.2% → **100%**，锁定 58.9% → **100%**，
  累计翻转 7311 次 → **1 次**，62 个赛道锥桶全覆盖；108 组参数里 102 组零判错（对参数不敏感）。
- 端到端实跑（`tools/run_live_test.sh`）：发布 60-65 个锥桶、输出收敛（投票中 → 0），
  与几何参考真值逐点比对 **63/63 完全一致、零错误**。图见 `figures/06-左红右蓝实测验证.png`。

## 「前方锥桶不上色」诊断 + 算法优化方案（同一会话）

用户报两个现象并要规划方案。

### 诊断结论（实测钉死）

1. **前方不上色（真 bug）**：`min_reliable_votes=2` 要求满权票，满权票只在投影落在"已驶过路径内部"
   时产生 → 前方锥桶永远不上色。这是唯一的真问题。
2. **"驶过未上色"/"只上一侧"是分析脚本假象**：去重聚类（1.2 m 网格）把同一锥桶算成两个质心，
   审计按最近参考锥桶匹配时对不上号。调试显示这些锥桶**节点已正确锁定**
   （如 (0.4,18.9) 旁轨迹#45 已锁红）。62 个锥桶 60+ 个正确，红蓝锁定率各 97%，无偏色。

### 关键参数实测（`tools/measure_head_range.py`）

车头朝向对前方锥桶判左右准确率：**0–5 m = 97.4%，5–8 m = 81.1%，8–12 m = 53.1%（近乎随机）**。
→ 前方暂定色可靠范围取 **8 m**（原 `head_range=12` 太宽）。

### 方案（已写成交付文档 `锥桶分色算法优化方案.md`）

三级状态机 UNKNOWN → PROVISIONAL → LOCKED：
- 判色仍用路径切向法（已验证 100%），不动。
- **PROVISIONAL**：前方 ≤8 m 锥桶用车头朝向 + 累积多数票，显示**降亮半透明**色。
- **LOCKED**：驶过后满权票 ≥2 且加权票 ≥6 且比例 ≥0.8，显示实心色，永久。
- 附带修复：`map_assoc_dist` 0.9→1.2（合并重复轨迹）、`head_range` 12→8、新增 `provisional_min_votes=2.0`。

方案写到结构体/函数/参数/发布/验证步骤级别，可直接交给弱模型实现。

## 修「右下角多出一排」+「赛道不完整」（同一会话，深度排查）

### 问题 1：右下角/底部多出一排红点 —— 已修复

实测参考库里锥桶到路径的距离分布：**边界排 0.00~2.88 m；赛道外还有一排真实物体在
3.59~8.98 m（28~93% 的帧可见、z≈0.19~0.51，是真东西但不是赛道边界）；11 m 外是杂点团块**。
原来 `path_gate = 5.0` 把 3.59~5.0 那部分赛道外物体也染成了红色。
**修：`path_gate` 5.0 → 3.2**（正好落在 2.88 与 3.59 之间的空档）。实跑验证多出的一排消失。

### 问题 2：「赛道不完整」—— 定位到三个独立原因，已修两个半

1. **`head_range` 形同虚设（真 bug，已修）**：`if (sqrt(best_d2) > path_gate_) continue;`
   里的 `best_d2` 对「车前方锥桶」而言是「到路径端点的距离」，而端点就在车上
   → 等价于要求「锥桶离车 < 3.2 m」，8 m 的前瞻完全没用。已改为前方用
   「距车距离 + 相对车头航向线的横向偏移」把关。
2. **锁定比例被降权票污染（已修）**：弯顶锥桶拿到大量降权票（车头朝向在弯上
   一半红一半蓝），把比例拉到 50/50 → 永远锁不上。已改为**锁定比例只看满权票
   （实测切向）**，降权票只用于暂定色。C++ `ConeTrack` 加 `red_rel/blue_rel`。
3. **只在车前方短暂看到的锥桶永远拿不到满权票（已加机制，但对最极端那个还没生效）**：
   实测某锥桶 600 帧只被看到 27 次、**全在车前方 5.8~13.9 m 的连续 27 帧**，
   只攒到 2.1 张降权票；车一转弯它就出视野。已新增 `rescoreTracks()`：
   **每帧用最新路径给未锁定轨迹重新评分**（判色核心抽成公用函数 `sideFor()`），
   `map_max_miss` 30→60 让候选活得更久。

### 现状（实跑 `/tmp/cone_v6`）

- 发布 57 个（29 红 + 28 蓝），锁定事件 56 条，**零错色**。
- 仍缺 `(8.81, 0.81)` 这一个（赛道东端弯顶）：它是真锥桶（27 个点、散布 0.08×0.13 m），
  但**节点从未为它建起轨迹**——待定列表里从未出现过它。`rescoreTracks` 没生效的原因待查
  （可能该帧观测的 `vote_w` 为 0 导致不建轨迹，而重评只针对已存在的轨迹）。

### 已加的诊断日志（有用，建议保留）

`addVote()` 里轨迹从未锁定→锁定时打印 `轨迹锁定 (x, y) -> 红/蓝`；
